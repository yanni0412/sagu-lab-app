# 도어온 — 스마트 도어락 원격 제어 앱 (프로토타입)

크라운 같은 원격 도어락 앱을 참고해 만든 **단일 HTML 웹앱**입니다.
지금은 실제 도어락 대신 **가상 도어락(MockLockDriver)** 으로 동작하므로
설치 없이 바로 눌러보며 화면·흐름을 확인할 수 있어요.

## 실행

```bash
# 저장소 루트에서
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000/doorlock/ 열기 (휴대폰 화면 크기 권장)
```

## 기능

| 탭 | 기능 |
|---|---|
| 홈 | 잠금 상태, **길게 눌러 원격 열기**(실수 방지), 눌러서 잠그기, 배터리·문 상태·자동잠금, 최근 출입 |
| 출입기록 | 날짜별 기록, 열림/잠김/경고 필터 |
| 출입키 | 임시 비밀번호(1회용 / 기간 / 요일·시간 반복) 생성·공유·삭제, 구성원 초대·권한 |
| 설정 | 자동잠금(시간), 이중잠금(원격 열기 차단), 침입 경보, 음량, 앱 비밀번호(실행·원격 열기 시 확인), 알림 종류, 도어락 추가/삭제 |

**데모 시뮬레이터**(설정 탭): 가족 지문 출입, 키패드 번호 입력(임시 비밀번호 검증, 5회 오류 시 침입 경보),
문 열어두기(10초 후 알림), 배터리 감소, 연결 끊김을 흉내 낼 수 있어요.

데이터는 브라우저 `localStorage`에만 저장됩니다. 앱 비밀번호는 SHA-256 해시로 저장해요.

## APK 설치 (안드로이드)

1. GitHub 저장소 → **Actions** 탭 → **Build DoorOn APK** 실행 결과로 들어갑니다.
   (`doorlock/` 또는 `doorlock-app/`을 수정해 push하면 자동 실행, 수동 실행도 가능)
2. 아래 **Artifacts**의 `dooron-debug-apk`를 내려받아 압축을 풀면 `app-debug.apk`가 나와요.
3. 휴대폰에 옮겨 설치합니다 ("출처를 알 수 없는 앱" 허용 필요).
4. 앱에서 블루투스·위치 권한을 허용해야 도어락을 찾을 수 있어요.

Capacitor 프로젝트는 `doorlock-app/`에 있고, 화면은 이 폴더(`doorlock/`)를 그대로 씁니다.
디버그 APK라 Play 스토어에는 올릴 수 없어요 — 스토어용은 루트 README의 서명 AAB 방식을 따라 하면 됩니다.

## 블루투스 도어락 (B안: 직접 연결)

준비물: **ESP32 보드** + 잠금장치(릴레이+솔레노이드, 모터식 도어락 드라이버, 서보 등) + (선택) 문 리드스위치·실내 버튼

1. Arduino IDE에 ESP32 보드 패키지를 설치하고
   `doorlock-app/firmware/doorlock_esp32/doorlock_esp32.ino`를 엽니다.
   맨 위 **하드웨어 설정**의 핀 번호를 내 회로에 맞게 고칩니다.
2. 업로드 후 시리얼 모니터(115200)를 열면 `보안 키: 0a1b…`(32자리)가 나옵니다.
3. 앱 → **설정 → 도어락 추가 → 블루투스 도어락** → 키 입력 → **기기 찾기** → `DoorOn Lock` 선택.
4. 홈 버튼을 길게 누르면 열리고, 실내 버튼·자동잠금·문 열림 경고가 앱 기록에 들어옵니다.

### 보안 구조

- 명령마다 도어락이 **일회용 난수(nonce)** 를 주고, 앱은 `HMAC-SHA256(보안 키, 난수‖명령)`을 붙여 보냅니다.
  키가 없으면 열 수 없고, 엿들은 명령을 다시 보내도(재전송 공격) 통하지 않아요.
- 잘못된 키로 5번 시도하면 30초 차단 + 앱에 침입 경고.
- 보안 키는 ESP32에서 무작위로 만들어 저장합니다(기본 키 없음). **BOOT 버튼 5초** = 키 재생성.

### 알려진 한계

- 상태 알림(잠김/열림)은 암호화되지 않아, 근처에서 블루투스를 엿보면 문 상태를 알 수 있어요(열 수는 없음).
- 앱의 보안 키는 휴대폰 `localStorage`에 저장돼요. 휴대폰을 잃어버리면 BOOT 5초로 키를 바꾸세요.
- 블루투스 범위(약 10m) 안에서만 동작해요. 밖에서 열려면 Wi-Fi 허브나 서버가 필요해요(A안).
- 임시 비밀번호는 예제 펌웨어에 키패드가 없어 기기에 적용되지 않아요.
- 펌웨어 컴파일은 같은 Actions 워크플로(`firmware` 작업)에서 검사해요. 실제 하드웨어 테스트는 아직 안 했어요.
  앱 쪽 프로토콜은 펌웨어 로직을 흉내 낸 가상 기기로 검증했습니다.
- 실제 출입문에 쓰기 전에, 정전·배터리 방전 때 **기계식 열쇠 등 비상 개방 수단**을 꼭 마련하세요.

## 다른 방식으로 연결하려면

`index.html`의 **3. 도어락 드라이버** 부분에서 `driverFor()`가 기기별 드라이버를 고릅니다.
제조사 클라우드 API가 있다면 포함된 `HttpLockDriver`를 쓰세요. **API 키·토큰을 앱 코드에 넣지 말고**
자체 서버를 두는 것이 안전합니다. 출입 기록·푸시 알림도 실서비스에서는 서버와 FCM이 필요해요.
